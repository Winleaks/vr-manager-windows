# Driver cash recovery — v0.1.127

Base: released v0.1.126. SQLite migration 27 retains all nine receipt fields and permits missing local financial associations for zero declarations only. Startup creates and verifies a pre-migration SQLite snapshot before applying the migration. Existing protected vaults and pending v0.1.126 encrypted saves keep their original canonical digest; the optional driver receipt history is added on the first financial operation, after a verified encrypted vault backup.

Only Writer receives platform commands. Normal payments retain the SQLite transaction. Protected payments use the existing encrypted outbox and verified Drive revision/manifest, then commit the operational receipt and cash delta in one SQLite transaction. Server acknowledgment is last. Permanent encrypted operation identities prevent replay even after the bounded general audit/idempotency list expires. A processing journal resumes incomplete work; a processed server operation missing from SQLite pauses synchronization instead of recreating cash.

## Containment

If ledger identities or versions disagree, the receiver pauses and retains its journals. Pause further synchronization on Writer; preserve SQLite, encrypted outbox and Drive vault. Do not restore an older database over new receipts or remove encrypted pending files. Fix forward after reconciling each operation. `supabase/rollback/driver_cash_routing_recovery.sql` restores the prior receiver functions without removing financial records or audit history; it does not undo already applied payments. Keep schema 27 and compatible clients when containing a deployment.
