# Financial PDF synchronization

SQLite on Writer remains authoritative. Database backup, normal PDF delivery and client-platform billing publication are separate flows. A successful database backup never acknowledges a PDF upload.

Migration 19 is additive and transactional, preceded by a verified SQLite snapshot. `document_sync_queue` contains only normal invoice/Credit Note IDs, generation, state, attempts, retry deadline, safe error and verification time. It contains no protected-register payloads or secrets. Existing noncancelled invoices with no Drive reference and credits with pending/error cloud status are queued, not reissued. Already confirmed historical documents are not bulk rewritten.

Invoice creation/revision/status and Credit Note creation/status update the queue inside the financial transaction. Writer PDF regeneration also enqueues the invoice, including open/print/share preparation. Viewer may save a local copy but cannot enqueue, retry or upload. Deleted/cancelled invoice jobs are removed by triggers, without deleting remote financial history.

The worker runs on startup and every 30 seconds, processing up to ten eligible documents serially per batch. Manual and automatic uploads share document locks; folder discovery/creation is serialized. Disconnection preserves work. Transient failures use exponential delay plus jitter, capped at roughly 15 minutes; eight failed attempts or permanent errors require explicit retry. No network calls are made from the status endpoint. Drive file requests in invoice upload and folder discovery use 30-second timeouts; a timed-out write is reconciled by identity before retry rather than assumed to have failed remotely.

Confirmation is conditional on the same database, Writer role and queue generation, after remote content checksum/size verification. A concurrent edit cannot be acknowledged by an older upload. The normal working PDF retains its Drive ID; legacy credits are moved and updated in place, not deleted/recreated. Immutable invoice publication snapshots retain revision-qualified names; fixed PDF metadata makes a retried revision byte-identical. No layout or financial formula changes are intended.

The global nonmodal banner shows pending/blocked counts and ten representative references/errors, with an accessible icon-only retry action on Writer. Viewer displays the state in its latest database replica, not a live assertion of remote state. Protected-register synchronization remains session-gated and is deliberately outside this queue.

Tests cover persistence/restart, rollback, role and database changes during IO, cancellation, stale completion, duplicate folders/files, response loss, deterministic PDFs, retry caps, redacted error categories, keyboard retry, Viewer denial and uninterrupted input focus. Local tests use synthetic data and provider doubles; they do not establish recovery on the real Writer/Drive account.

Local verification on 2026-09-08: 261 automated tests passed; TypeScript and renderer/main/preload production build passed; targeted lint passed (repository-wide lint retains existing warnings). Browser regression suite passed both Credit Note entry paths, normal/protected numeric editing, company search, the new document banner, keyboard retry, Viewer denial and focus retention. A separate visual browser check confirmed the banner renders without an error overlay. Windows installed-app and real Drive delivery have not been verified for this change.

Release requirements: Windows installed upgrade through migration 19, one real pending invoice and credit, verify existing Drive IDs/bytes, reconnect/restart, and check the banner clears only after verification. Preserve the pre-migration backup; prefer a forward fix if needed. Do not delete/reissue invoices or replace current business data to recover a PDF transfer. No production data or Drive files are modified by local development/tests, and publication requires separate user authority.
